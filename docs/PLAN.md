## 1단계 — 기획서

- 이 문서를 쓰고 사용자 승인을 받는다.
- 이미 저장소에 있는 뼈대(에이전트·스킬·스크립트 초안)는 지우지 않고, 아래 각 단계에서 이 기획서에 맞게 고쳐 쓴다.

### 지켜야 할 조건 (전 단계 공통)

| 단계 | 조건 |
|---|---|
| 리서치 | 관심사를 관점별로 나눠 **관점마다 서브에이전트 하나**로 병렬 리서치 · **로그인·결제 없는 공개 소스만** |
| 작성 | **항목마다 출처 링크** · 스타일은 HTML 안(인라인)에 · **외부 파일·스크립트 금지** |
| 발송 A | 연결된 Gmail 커넥터 · HTML은 **첨부가 아니라 본문** |
| 발송 B | Gmail SMTP · 계정 정보는 **루트 `.env`** 에서 읽기 · 앱 비밀번호는 **코드·기획서에 적지 않음** · HTML은 본문 |
| 업무 폴더 | 뉴스레터마다 `{오늘 날짜}_{주제}` 폴더를 새로 만들고, 관점별 리서치와 HTML을 **만드는 즉시 그 폴더에 저장** |

## 2단계 — 메일 발송 환경

### 할 일
1. **경로 A (Gmail 커넥터)**
   - 이 세션에 연결된 Gmail 커넥터가 어떤 계정인지 확인한다 (`moogm99@gmail.com`인지).
   - 다르면 claude.ai 설정에서 커넥터를 `moogm99@gmail.com`으로 다시 연결하도록 안내한다.
   - 본문만 있는 테스트 메일을 `moogm99@gmail.com`으로 보낸다 (사용자 확인 후).
2. **경로 B (Gmail SMTP)**
   - 2단계 인증 → 16자리 앱 비밀번호 발급 안내 (완료).
   - 루트 `.env` (커밋 안 됨): `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587` (이 세션에는 비밀번호 빈칸으로 생성 완료).
   - 클라우드 세션은 SMTP 연결이 막혀 있으므로, 테스트는 **사용자 컴퓨터에서** `python3 scripts/send_smtp.py --test`로 한다.
3. `config/newsletter.toml`의 `recipient`를 `moogm99@gmail.com`으로, `send_time`을 `10:00`으로 바꾼다.

### 완료 기준
- 경로 A 또는 B로 보낸 테스트 메일이 받은편지함에 도착 (스팸함이면 "스팸 아님" 처리).

## 3단계 — 병렬 리서치

### 관심사 × 관점 구조

뉴스레터 한 편에 관심사 5개 영역을 모두 담는다. 서브에이전트는 **관점마다 하나(총 4개)**, 각자 자기 관점으로 5개 영역을 훑는다.

| 관점 서브에이전트 | 주가 추이 | 경제·시장 | AI·AX | 반도체 | 마케팅·콘텐츠 |
|---|---|---|---|---|---|
| ① 핵심 숫자·데이터 | 종가·등락률·거래 특이점 | 금리·환율·주요 지표 | 투자액·사용자 수·성능 수치 | 출하·가격·점유율 | 광고비·플랫폼 지표 |
| ② 원인·배경 분석 | 오르고 내린 이유 | 지표 변화의 배경 | 새 발표가 나온 배경 | 공급망·수요 변화 이유 | 트렌드가 뜨는 이유 |
| ③ 실무 적용·시사점 | 투자자가 볼 점 | 내 돈·사업에 주는 영향 | 바로 써 볼 도구·사례 | 관련 산업·직무 영향 | 바로 써 볼 전략 |
| ④ 향후 전망·일정 | 실적 발표·이벤트 일정 | 금리 결정·지표 발표일 | 출시 예정·행사 | 실적·신제품 일정 | 행사·정책 변화 일정 |

### 주가 대상 (승인 때 확정)
제안값: **코스피, 코스닥, S&P 500, 나스닥, 삼성전자, SK하이닉스, 엔비디아, 원/달러 환율**
- ~~공개 시세 데이터를 스크립트로 가져온다~~ → **3단계 시작 때 확인 결과 불가**: 클라우드 환경이 스크립트의 외부 접속(Yahoo·Stooq·네이버 금융 등)과 대부분의 WebFetch를 막는다.
- 대신 **핵심 숫자·데이터 서브에이전트가 WebSearch(extended)로 공개 출처 두 곳을 대조**해 `00_시세.json`에 숫자·기준 시각·출처 2개를 함께 저장한다. 한 곳에서만 나온 숫자는 "단일 출처"로 표시한다.
- 주가 숫자 옆에는 항상 기준 시각(예: "10/24 종가")을 적는다.

### 진행
1. `scripts/make_workdir.py` → `newsletters/2026-10-27_데일리브리핑/` 생성, `run.json` 저장.
2. `perspective-researcher` 서브에이전트 4개를 **한 번에 동시에** 실행 → 각자 저장 (핵심 숫자·데이터 담당은 `00_시세.json`도 저장):
   - `01_핵심-숫자-데이터.md` · `02_원인-배경-분석.md` · `03_실무-적용-시사점.md` · `04_향후-전망-일정.md`
3. `scripts/check_research.py` → 파일 4개 존재, 관심사 섹션 5개, 항목마다 링크, 막힌 도메인 없음, 시세 8개의 기준 시각·출처 확인.

### 공개 소스 규칙
- 검색 때 로그인·결제 사이트(`blocked_domains`: WSJ, FT, Bloomberg, Economist, NYT, LinkedIn, X 등)를 제외한다.
- 원문이 로그인·구독·결제 화면으로 막히면 버리고 다른 공개 매체로 바꾼다. 캐시·아카이브로 유료 기사를 여는 우회는 금지.
- 기간: 최근 24시간 (주말·휴장 다음 날은 72시간까지).

### 완료 기준
- 수동 실행 1회로 업무 폴더에 `00_시세.json` + 관점별 `.md` 4개가 생기고 점검을 통과한다.

## 4단계 — HTML 뉴스레터

### 구성 (위에서 아래로)
1. 머리말: `AutoAX 데일리 브리핑 · 2026-10-27 (월)`
2. **오늘의 핵심 3줄** — 줄마다 출처 링크
3. **시세 표** — 지수·종목·환율, 종가와 등락률 (오르면 빨강, 내리면 파랑 — 한국식)
4. **관심사별 섹션** — 경제·시장 → AI·AX → 반도체 → 마케팅·콘텐츠. 각 항목에 관점 꼬리표(`숫자` `원인` `시사점` `전망`)를 붙인다.
5. **이번 주 일정** — ④ 관점에서 모은 날짜순 일정
6. 바닥글: 자동 작성 안내, "투자 권유가 아님" 문구, 리서치 원본 폴더 이름

### 규칙
- 항목마다 출처 링크 (리서치 파일의 링크를 그대로 사용, 새로 만들지 않음).
- 표(table) 레이아웃, 폭 640px, 인라인 스타일만. `<script>`, `<link>`, `@import`, 이미지·iframe(`src=`), CSS `url()`, `<form>` 금지.
- 100KB 미만 (Gmail은 102KB 넘으면 본문을 자름).
- `scripts/check_html.py`로 점검 → 통과할 때까지 수정 → `newsletter.html`을 업무 폴더에 즉시 저장.

### 완료 기준
- 3단계 결과로 만든 `newsletter.html`이 점검을 통과하고, 미리보기 화면을 사용자가 확인.

## 5단계 — 실제 발송

### 순서
1. `run_log.md`에 이미 메시지 ID가 있으면 건너뜀 (중복 발송 방지).
2. `check_html.py` 다시 통과 확인.
3. **경로 A**: Gmail 커넥터 `send_message` — `to`=moogm99@gmail.com, `subject`=`[AutoAX] 10/27(월) 데일리 브리핑 — {오늘의 핵심 한 줄}`, `htmlBody`=HTML 전체, `body`=텍스트 요약, 첨부 없음.
4. 경로 A 실패 시 **경로 B**: `scripts/send_smtp.py {업무 폴더}` — `.env`로 로그인, `text/plain` + `text/html` 본문, 첨부 없음 (사용자 컴퓨터에서 실행할 때).
5. 결과(경로, 메시지 ID 또는 오류)를 `run_log.md`에 기록. 비밀번호는 어디에도 기록하지 않음.

### 완료 기준
- 4단계에서 만든 실제 뉴스레터를 받아 Gmail 웹과 모바일 앱에서 확인: 레이아웃, 링크, 한글, 시세 표 색.

## 6단계 — 통합 테스트·매일 오전 10시 예약

### 통합 테스트
1. "오늘 뉴스레터 만들어 줘" 한 마디로 2~5단계가 처음부터 끝까지 자동으로 도는지 확인.
2. 실패 상황 점검: 관점 하나 실패 시 나머지로 발송 / 시세 소스 실패 시 표에 "데이터 없음" / 같은 날 재실행 시 `_2` 폴더 + 중복 발송 없음.
3. 걸린 시간을 재서 예약 시각을 정한다.

### 매일 오전 10시 예약
- 클라우드 예약 작업 (컴퓨터가 꺼져 있어도 실행): 매일 **09:4x 한국 시간**에 시작해 10:00 전후 도착. 통합 테스트에서 잰 소요 시간으로 시작 시각을 조정.
  - 실행마다 새 세션, Gmail 커넥터 허용, 끝나면 휴대폰 알림.
  - 경로 A로 발송 (클라우드에는 `.env`가 없고 SMTP도 막혀 있음).
  - 업무 폴더는 발송 후 커밋해 저장소에 올려 보관 (클라우드 세션은 끝나면 파일이 사라지므로).
- 대안: 사용자 컴퓨터 cron/작업 스케줄러 + 경로 B.

### 완료 기준
- 예약 등록 후 다음 날 오전 10시 전후 메일이 자동으로 도착하고, 저장소에 그날 업무 폴더가 올라옴.

## 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 클라우드에서 SMTP 막힘 | 클라우드 예약은 경로 A, 경로 B는 사용자 컴퓨터 전용 |
| Gmail 커넥터가 다른 계정에 연결됨 | 2단계에서 확인, 필요하면 재연결 |
| 공개 시세 소스가 이 환경에서 막힘 | **실제로 막힘 (3단계 확인)** → WebSearch(extended)로 출처 두 곳 대조, 숫자마다 출처·기준 시각 표시 |
| 관심사 5개 × 관점 4개로 뉴스레터가 길어짐 | 관심사마다 최대 3항목, 100KB 점검 |
